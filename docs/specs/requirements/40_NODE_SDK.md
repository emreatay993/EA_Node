# Node SDK Requirements

## Contracts
- `REQ-NODE-001`: Node SDK shall include typed `PortSpec`, `PropertySpec`, and `NodeTypeSpec`. The unified workflow-interface contract is a separate planned scope under `REQ-NODE-036`; it does not widen this requirement or its existing proof.
- `REQ-NODE-002`: Node plugin contract shall provide `spec()` and `execute(context)` methods.
- `REQ-NODE-003`: Node registry shall support registration, instantiation, and filtered discovery by normalized `category_path`, including descendant-inclusive prefix matching, path-backed `category_paths()` discovery, and derived display labels for presentation; display text is not a compatibility alias.

## Properties and Ports
- `REQ-NODE-004`: Node properties shall be declarative and editable from inspector. Workflow-interface defaults and publication semantics are a separate planned scope under `REQ-NODE-036`; they do not widen this requirement or its existing proof.
- `REQ-NODE-005`: Port exposure toggles shall be driven by node instance state and reflected immediately in UI. Workflow-level interface exposure is a separate planned scope under `REQ-NODE-036`; it does not widen this requirement or its existing proof.
- `REQ-NODE-006`: `PortKind` shall be `Literal["data", "flow"]`. Registry validation shall reject `exec`, `completed`, `failed`, and every alias or adapter for those retired control kinds; `flow` remains reserved for unrelated passive authoring surfaces.
- `REQ-NODE-038`: The public SDK shall define `DataPath = tuple[int, ...]`, `DataAccess = Literal["item", "list", "tree"]`, `DataTreeModifier = Literal["graft", "flatten", "simplify", "reverse", "clean"]`, and an immutable `DataTree` whose lexicographically sorted paths map to ordered item sequences. Only `DataTree` represents tree topology; ordinary Python lists and dictionaries remain Item values unless a List-access output explicitly returns a non-string sequence.
- `REQ-NODE-039`: `PortSpec.data_access` shall default to `item`, remain author-declared rather than ordinarily user-editable, and describe structure separately from the element `data_type`. `ExecutionContext` shall expose `target_path`, `target_iteration`, and `iteration_count` while retaining `trigger`; `NodeResult.completed` shall be removed; and every output shall validate as exactly one Item value (including explicit `None`), a non-string List sequence, or a `DataTree` according to its declared access.
- `REQ-NODE-040`: Queue-safe runtime serialization shall define a recursive `data_tree` marker whose branch items may contain the existing artifact, array, tabular, worker-handle, and explicit-`None` runtime values without flattening or losing path order.
- `REQ-NODE-045`: The SDK shall expose first-class ordered `Interval1D` values through `INTERVAL_1D_DATA_TYPE = "interval_1d"` and `prop_interval_1d(...)`; the helper shall select `inline_editor="interval_slider"`, bounded finite metadata, and an author-selected increasing or decreasing direction without sorting endpoints. `PropertySpec` shall also expose code-selected `searchable=True` only for static enum controls and `enabled_when=PropertyConditionSpec(...)` only for a same-node scalar value-IN condition. `SettingsGroupSpec` shall preserve declared group order, and same-key `uses_property_default=True` inputs shall remain paired with their authored properties. The public guide shall demonstrate these declarations without adding a production Signal Plot node or a node-local UI factory.
- `REQ-NODE-046`: The public Node SDK shall expose `DynamicPortGroupSpec` for node-owned dynamic port declarations. Each immutable registered declaration shall identify a stable group key and direction, its ordered backing-property key, capability limits, and immutable pure deterministic callbacks only for resolving the group's ordered ordinary `PortSpec` values from node properties, creating a new stable port key, and optionally validating or canonicalizing a proposed structural key rename. These callbacks shall not mutate the graph or backing properties. The same registered resolver output shall be authoritative for identical graph, UI, and runtime port projection. Group declarations and resolved `PortSpec` metadata are code-authored, not user-editable metadata, and no standalone reorder action is part of this contract.
- `REQ-NODE-048`: The built-in catalog shall register exactly `ssh_sftp.secret`, `ssh_sftp.host`, `ssh_sftp.run_command`, `ssh_sftp.run_script`, `ssh_sftp.upload`, and `ssh_sftp.download` under `Control > SSH/SFTP`, using ordinary declarative `NodeTypeSpec`, `PortSpec`, and `PropertySpec` metadata. Credential ports shall accept only `secret_data`, operation host ports shall accept only `ssh_sftp_host_data`, upload/download Sources shall use List access, and the Host value shall be a queue-safe tagged data descriptor containing endpoint and authentication configuration rather than a live client, transport, or session. The six built-ins shall use the shared registry, graph/Inspector projection, runtime snapshot, and worker plugin callback path without dynamic ports, node-specific QML, a parallel UI factory, or a connector service.

## Decorator Authoring (RC2)
- `REQ-NODE-007`: SDK shall provide decorator helpers to author nodes without manually constructing `NodeTypeSpec`; node authors shall pass `category_path=` tuples rather than `category=`, and external plugins must treat this as a breaking authoring change while using derived display labels for presentation only.
- `REQ-NODE-008`: Decorator-authored nodes and class-spec-authored nodes shall be registry-compatible.
- `REQ-NODE-016`: `NodeTypeSpec` shall expose `runtime_behavior` plus `surface_family` / `surface_variant` hints and additive `render_quality` metadata (`supported_quality_tiers`) as planned-public surface descriptors so the registry can describe passive-vs-active behavior, host-routed canvas surfaces, and supported quality tiers declaratively with safe defaults when the field is omitted.
- `REQ-NODE-017`: node authoring contracts shall support `flow` port kinds and declarative editor hints such as multiline text and filesystem path pickers for passive-node properties through the explicit surface/input contract.
- `REQ-NODE-020`: passive flowchart SDK contracts shall publish exactly four stored ports keyed `top`, `right`, `bottom`, and `left`; those ports shall use `direction="neutral"`, `kind="flow"`, `data_type="flow"`, `allow_multiple_connections=True`, and a `side` value that matches the stored key, while non-flowchart specs keep the existing fixed-direction port contract. Flowchart variants that are library-icon-like rather than text-container-like shall keep their `title` label for catalog/search and may ship with an empty `body` default so graph rendering does not paint the library label inside the silhouette; the timestamp variant shall use a date placeholder body rather than the catalog label and shall expose a `live` boolean property for live timestamp rendering.
- `REQ-NODE-021`: node SDK and built-in catalog shall define `passive.annotation.group_backdrop` as a zero-port, collapsible, passive annotation node with `surface_family="group_backdrop"` and `surface_variant="group_backdrop"`, while sticky note, callout, and section header remain connectable note-style annotations instead of grouping items.
- `REQ-NODE-022`: execution-facing SDK contracts shall support `RuntimeArtifactRef` values plus `ExecutionContext.resolve_path_value()` and `ExecutionContext.runtime_artifact_ref()` helpers so node authors can emit or consume `saved://...` and `temp://...` project-file refs without reimplementing queue serialization or path resolution.
- `REQ-NODE-025`: the node SDK and built-in catalog shall define `dpf.viewer` as the canonical viewer-family DPF node with `surface_family="viewer"`, `output_mode` defaulting to `both`, and `viewer_live_policy` constrained to `focus_only|keep_live`, while upstream DPF compute nodes continue to exchange handle-backed data rather than live viewer payloads and viewer transport remains behind explicit runtime backend descriptors.
- `REQ-NODE-028`: `NodeTypeSpec.icon` remains the authoring field, but the node-title icon contract shall treat it as a local image-path reference only: built-in relative paths resolve from the repo-managed node-title icon asset root, file/package plugin relative paths resolve only from safe provenance roots, safe absolute plugin paths remain allowed when the file exists, supported suffixes are `.svg`, `.png`, `.jpg`, and `.jpeg` case-insensitive, empty values, symbolic icon names, remote/data URLs, missing or unreadable files, unsupported suffixes, and unsafe entry-point cwd fallbacks resolve to no title icon, the built-in non-passive catalog ships repo-managed asset paths instead of symbolic header-icon names, the derived live `icon_source` payload is populated only for `active` and `compile_only` nodes when local resolution succeeds, eligible repo-managed SVG title icons also derive live `icon_theme_aware=True` so QML can theme-tint them without per-node conditions, passive flowchart library visuals derive from `surface_family="flowchart"` plus `surface_variant` instead of parallel icon metadata, and other passive node-library visuals may derive separate display-only preview metadata from `icon`, `runtime_behavior`, `surface_family`, and `surface_variant` without making passive graph title-row icons eligible.
- `REQ-NODE-029`: the node SDK and built-in catalog shall define `io.folder_explorer` as a passive File I/O node with `surface_family="folder_explorer"`, `surface_variant="classic"`, a persisted `current_path` folder property using the filesystem path editor hint, a `current` path output for the selected/current folder, runtime exclusion from flattened execution graphs, and no persisted navigation/search/sort/selection/context-menu/maximized surface state.
- `REQ-NODE-030`: the node SDK and built-in catalog shall define `excalidraw.board` as the COREX-owned passive Excalidraw board node with `runtime_behavior="passive"`, `surface_family="web"`, `surface_variant="excalidraw_board"`, hidden JSON project properties `excalidraw_state` and optional `excalidraw_preview_ref`, imported-image refs under `excalidraw_state.files[*].artifact_ref`, no execution ports, and no arbitrary third-party web UI registration surface for external plugins outside explicit future surface/toolchain descriptors.
- `REQ-NODE-032`: During pre-release modernization, old plugin import aliases, class-probe loading, non-descriptor authoring surfaces, and creation-wizard contracts are not compatibility commitments; supported plugin contracts shall flow through explicit `PluginDescriptor`, `PluginContractManifest`, `RuntimeBackendSpec`, `ToolchainSpec`, `ArtifactDescriptor`, and `SurfaceCapabilitySpec` records. `CreationProfile`, `WizardSpec`, their generated-file, validation, property-override, and post-create contract types, `PluginDescriptor.creation_profile`, registry creation-profile accessors, and corresponding UI payloads/actions shall be removed without aliases. Python plugin descriptors remain loadable, but manifest records are the canonical place to describe runtime backend adapters, optional library/compiler requirements, version checks, compiled/native artifact preparation, and plugin-declared surface capability metadata. Remote endpoint trust and capability discovery are separate planned scopes under `REQ-INT-018` and `REQ-EXEC-020`; they do not widen this requirement or its existing proof.
- `REQ-NODE-033`: the node SDK and built-in catalog shall define `web.page_viewer` as a passive Web category node with `runtime_behavior="passive"`, `surface_family="web"`, `surface_variant="page_viewer"`, a safe persisted `start_location` browser configuration property, a `persist_browser_state` toggle plus optional hidden browser-state/preview properties so the surface reopens at the user's last visited location, passive execution behavior, and no scraper, DOM extraction, credential manager, browser automation, or multi-tab semantics.

Example:

```python
from ea_node_editor.nodes.decorators import node_type, in_port, out_port, prop_int

@node_type(
    type_id="demo.scale",
    display_name="Scale",
    category_path=("Core",),
    icon="icons/scale.svg",
    ports=(in_port("value", data_type="float"), out_port("scaled", data_type="float")),
    properties=(prop_int("factor", 2, "Factor"),),
)
class ScaleNode:
    def execute(self, ctx):
        return NodeResult(outputs={"scaled": float(ctx.inputs.get("value", 0.0)) * int(ctx.properties["factor"])})
```

`category_path` accepts `1..10` non-empty trimmed string segments. The SDK
joins display text with ` > `, for example `("Ansys DPF", "Compute")` displays
as `Ansys DPF > Compute`; the separator is not a parser contract and is chosen
to avoid ambiguity with existing single labels such as `Input / Output`.

- `REQ-NODE-035`: COREX shall register `engineering.cad_import`, `engineering.fe_import`, and `model.viewer` as built-ins. Import nodes accept an optional `path:path` input plus direct Browse property and emit `engineering_scene`; the viewer accepts one required scene plus one optional overlay and emits `viewer_session` plus `engineering_selection_set` without DPF aliases or compatibility shims.

## Planned Public Contracts
- `REQ-NODE-036`: The Node SDK shall define a planned unified workflow-interface contract for stable, typed, named inputs and outputs with direction, data access or passive-flow semantics, required or optional state, defaults, exposure, and compatibility; the same contract shall describe top-level, nested, published, linked, and headless workflows, and invalid or ambiguous interfaces shall fail validation instead of being inferred from presentation state. Acceptance of this contract is a prerequisite for permissioned agent orchestration under `REQ-ARCH-020` and `REQ-EXEC-022`. Evidence crosswalk: `SYN-OPP-0003`.
- `REQ-NODE-037`: The Node SDK shall define planned solver-neutral FEA process contracts for model preparation, materials, meshing, conditions, loads, solve, and result stages; stage inputs and outputs shall carry explicit type, units, coordinate-system, scoping, and provenance semantics while solver-specific extensions remain namespaced and capability-gated. This requirement shall not change the delivered `engineering.cad_import`, `engineering.fe_import`, or `model.viewer` contracts in `REQ-NODE-035`. Evidence crosswalk: `SYN-OPP-0007`.
