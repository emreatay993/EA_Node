## Cross-layer feature routes

The [startup map](subsystems/startup_and_bootstrap.md) records the experimental
FluentWinUI3 Windows default and its local Qt runtime DLL prerequisite.

Shared Qt dialog styling preserves button content space when the default role changes after layout. The PyQt dialog/theme map owns label visibility and keyboard-acceptance coverage for input and message dialogs.

Unused Model Viewer inputs share the execution-owned computational projection.
Native CAD CURRENT reads retain process resources with validated provenance;
viewer label changes preserve actors, camera and previews through history and
refocus. Execution, nodes, viewer surfaces, engineering-viewer and run-controller
maps own the contract and its real default-worker proof.

The [Python Script authoring route](feature_routes/python_script_authoring.md)
owns the desktop builder/editor, type guidance, scoped source edits, sections,
native-field drafts and isolated preview. Graph-owned preparation/Apply retains
rename identities and history; shared headerless settings rows keep script
controls below main ports with compact geometry independent of socket exposure.
The Nodes map owns its `Code` Library category and `code.python_script` ID;
the Persistence map owns migration of the former `core.python_script` ID on open.

The viewer-session route owns the engineering interactor's native surface boundary, established before host attachment so OpenGL viewers can coexist with the Qt Quick graphics backend.

The top-right toolbar uses reusable `ZoomControl.qml` for continuous slider and numeric zoom requests; `ViewportBridge` owns zoom state and the 10-500% clamp, including restored view/scope cameras. The QML shell map records component and real-shell proving tests.

The [board editor route](feature_routes/excalidraw_web_host_real_editor.md) owns snapshot debounce/export/close coordination, revision-gated artifact commits, visual-content identity across project saves, and native canvas freshness/error states. Stale snapshots are hidden immediately after edits; the editor is the only drawing renderer.

Panel value interpretation spans the passive surface editor/badge, data-control runtime, and project/fragment property migration. The passive surfaces map owns UI/runtime evidence; serialization migration owns the legacy flag conversion.

Shared node-toolbar Expand/Collapse and Run-options icons are owned by the floating-toolbar route and the shell icon registry.
The surface loader retains action owners for active collapsed-node toolbars; hidden body input and native viewer/plot activity remain disabled.
Ordinary active/compile-only cards fit current content even with saved custom dimensions; passive and panel-like surfaces retain manual sizing, with exact `model.viewer` as the sole active-node exception and a drag-start aspect-ratio lock. Standard widths separate top-level port columns from settings headers and expanded controls. Graph Scene Payload owns sizing/anchor coverage and the real-canvas toggle regression.
Graphics Settings > Canvas > Nodes offers app-persistent expanded-width retention through the workspace presenter and scene-bound payload provider; ordinary card height still fits visible settings.
Settings-section size transitions use shared 180 ms width/height animations with interpolated headers and port anchors, clipped revealed controls that retain their enabled appearance and publish hit regions bounded to their live clips, and presentation-only member grips during collapse. Tagged canvas geometry synchronizes connections and yields to manual resize ownership; Surface Input owns the animation regression.

## Current ownership notes

- Swimlane pools and lanes are Group backdrops (`group_backdrop` family, variants `swimlane_pool` / `swimlane_lane`), so lane membership is the Group area rule and a lane drag carries its nodes. The Library offers the lane ("Swimlane"); a pool forms around two or more lanes and dissolves when one is left (`LIBRARY_HIDDEN_NODE_TYPE_IDS` keeps the pool out of the Library). The stacked-lane rule is pure (`ea_node_editor/graph/swimlane_layout.py`); `ea_node_editor/ui_qml/graph_scene_mutation/swimlane_ops.py` owns the commands, the read-only live previews and the capture/settle pass that the move, resize, create, paste, delete, collapse/expand, align, wrap and Tidy paths run in their own undo step. The canvas applies the previews through `ea_node_editor/ui_qml/components/graph_canvas/GraphCanvasSwimlanePreview.qml` (a lane drag in its pool is a reorder, and the lane a drag drops into lights up); the Inspector's Lanes section is `ea_node_editor/ui_qml/components/shell/InspectorSwimlaneLanesSection.qml`. The lane-aware Tidy is `_resolve_swimlane_pool` in `ea_node_editor/graph/transform_tidy_layout.py`. Backdrop hosts now stack by `backdrop_depth` (`GraphNodeHost.qml`), so a nested Group or lane is drawn and clicked above the backdrop around it. The [swimlane route](feature_routes/swimlane_pools_lanes.md) owns the proof: `tests/test_swimlane_layout.py`, `tests/test_swimlane_scene_ops.py`, `tests/test_swimlane_tidy_layout.py`, `tests/test_swimlane_persistence.py`, `tests/test_swimlane_shell.py`; the automation route owns `tests/automation/test_handlers_swimlanes.py`.
- Subnode boundary edge enablement is graph-owned: inner pin-segment toggles expand recursively to matching upper shell segments before validation, while the scene mutation layer publishes all changed edge records and keeps one history action. The graph-domain, nested-subnode, and edge-routing maps cover the contract and focused tests.
- Group membership is area-based for expanded Groups and identity-based for collapsed Groups and the Groups hidden inside them. The pure rules (owner rule, collapsed-body top-left corner containment, freeze/clear of the persisted `NodeInstance.held_member_ids` lists, held-member carry) live in `ea_node_editor/graph/group_backdrop_geometry.py`, and load/paste sanitizing in `ea_node_editor/graph/hierarchy.py`. Scene-side Group geometry for mutations is `ea_node_editor/ui_qml/graph_scene_mutation/group_scope.py`, the level-by-level make-room cascade on every expand is `collision_avoidance_ops.py`, and stray growth, older-file list fill-in, and Peek additions are `group_backdrop_ops.py`. The Group route owns the contract with `tests/test_group_backdrop_identity_membership.py` and `tests/test_group_scope.py`; the payload-projection, graph-actions (Tidy at pill size), clipboard/history, persistence and serialization, automation, and graphics-preferences ("Make room" default, `strategy_revision` 2) maps own their consumers.
- Flowchart body text sits in the shape's inscribed area: `ea_node_editor/ui_qml/components/graph/passive/FlowchartShapeGeometry.js` resolves each variant's contract `body_text_placement` against the silhouette parameters it shares with `FlowchartShapeCanvas.qml`. The `body_fit` mode (clip, grow, shrink) belongs to the [passive surface route](feature_routes/passive_surface_loading_contracts.md): grow persists through the resize commit path (`resizeFinished` -> `set_node_geometry`, one undo step) and keeps square variants square, while shrink and the overflow mark (elided last line, pill for markdown) are opt-in `GraphRichTextBlock.qml` flags. `tests/qml_quick/tst_graph_node_host.qml`, `tests/graph_surface/inline_editor_suite.py`, and `tests/test_flowchart_visual_polish.py` own the proof. The automation `node.fit_text` op (MCP `node_fit_text`) reaches the drawn surface through `ea_node_editor/ui/shell/automation/canvas_surfaces.py` and belongs to the [automation route](feature_routes/automation_api_mcp.md), proved by `tests/automation/test_handlers_shell.py`.
