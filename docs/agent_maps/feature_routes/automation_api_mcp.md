# Automation API And MCP Server

Lookup aliases: `automation api`, `mcp server`, `corex-mcp`, `agent automation`, `CorexClient`, `graph.apply`, `--automation`, `private instance`, `automation handlers`.

## Purpose
Use this for the public programmatic control surface of COREX: the loopback NDJSON automation protocol, the declarative op catalog, the GUI-thread bridge and per-domain handlers that call existing owners, the stdlib `CorexClient` + launcher (`auto` / `attach` / `private` modes), and the `corex-mcp` MCP server with embedded agent guidance. It is a local opt-in developer automation surface, not permissioned agent orchestration (`REQ-ARCH-020/EXEC-022/UI-058` stay blocked). User-facing documentation: `docs/AUTOMATION_API_GUIDE.md`.

## Do Not Start Here
- `ea_node_editor/ui/shell/composition/` for automation wiring; the server starts from `app.py` after the splash and the pinned `ShellServices` shape is untouched.
- `ea_node_editor/graph/model.py` private record writers or `GraphRecordMutation` for handler mutations; handlers go through `host.scene` (`GraphSceneBridge`) and the navigation / document-IO seams.
- `ea_node_editor/ui/shell/controllers/graph_action_controller.py` `trigger` for automation; many action ids open dialogs or touch the OS clipboard.
- `ea_node_editor/execution/` for run polling; `run.status` polls `ShellRunState` from a bridge-owned timer (the repo pins the `execution_event` connect count at 1).

## Common Changes
- New op: add an `OpSpec` to the domain module under `ops/`, add the handler to the matching `handlers/<domain>.py` `HANDLERS` table, add a `client_api` method, regenerate the guide reference with `python -m ea_node_editor.automation.docgen --update-guide` (`tests/automation/test_docgen.py` fails on drift), extend `tests/automation/test_catalog.py` expectations.
- New error code: append to `errors.ERROR_CODES` with an imperative default hint; regenerate the guide.
- Dialog-free seams used by handlers: `WorkspaceNavigationController.create_workspace_named` / `rename_workspace_to` / `close_workspace_noninteractive`, `WorkspaceViewNavOps.create_view_named` / `rename_view_to` / `close_view(show_errors=False)`, `ProjectDocumentIOService.save_project_to_path` / `open_project_path_noninteractive` / `new_project_noninteractive` / `document_io_active`.
- Startup without a restorable session calls `ProjectDocumentIOService.activate_project_solution_session` for the blank project (otherwise the first Save fails with `save_solution_stage_failed`); `_install_project` uses the same method.
- Capture: `CanvasExportPresenter.capture_canvas_view_pngs` renders offscreen only when node shadows are disabled during the grab (`ShellWorkspacePresenter.set_graphics_node_shadow`); shared numeric helpers live in `ea_node_editor/ui/canvas_view_export.py` (`positive_capture_dimension`).
- Spawned instances: `COREX_SESSION_STATE_DIR` (settings seam) isolates autosave / last-session / staging; `EA_NODE_EDITOR_BOOTSTRAPPED=1` skips the venv re-exec so the launcher-generated instance id matches discovery.
- Owner facts handlers depend on: passive flow ports are neutral ports keyed `top|right|bottom|left`; flowchart / annotation / group-backdrop titles live in `properties["title"]`; flowchart shapes draw `properties["body"]`; on the classic shapes (start, end, process, decision, document, connector, input_output, predefined_process, database) the body defaults to the shape name and `node.add` / `node.update` titles also drive an untouched body; `passive.annotation.text` content key is `text`; `media.panel` and `data.panel` are active nodes; `propagate_passive_node_style` propagates along edges, not by type; style schemas accept agent-friendly aliases (`fill_color_end` -> `gradient_color`, edge `color|width|pattern|label_color` -> `stroke_*` / `label_text_color`, text `color` -> `text_color`) and `catalog.style_schema` returns the persisted keys.
- `node.update` `width` / `height` are drawn sizes, the ones node summaries report (`AutomationContext.node_bounds`); `scene.resize_node` stores the height counting the port rows a hide-optional-ports view leaves out, so in such a view a width-only update keeps the drawn height. Focused: `tests/automation/test_handlers_nodes.py`.
- Layout ops: `layout.arrange` maps `align_*` to `GraphSceneBridge.align_selected_nodes` (the API-only `center_x` / `center_y` modes live in the pure builder `ea_node_editor/graph/transform_layout_ops.py::build_alignment_position_updates`, no menu entry), `distribute_*` to `distribute_selected_nodes`, `match_width|height` to `set_selected_same_type_size` (passive, same `type_id`, first listed node is the reference); `layout.straighten` wraps `straighten_selected_connections` and verifies each wire afterwards from `scene.edges_model` rows (`sx/sy/tx/ty`, `source_port_side` / `target_port_side`, port-direction fallback), reporting `mixed_port_sides` elbows, `unresolved_offset` wires, and ends the scene would not move. Layout handlers act only on drawn, selectable nodes (`_usable_node_ids`: locked nodes, collapsed-Group members, comment-peek exclusions are reported, never moved), and a collapsed Group they move carries its held members (the scene's layout-update path); align and distribute place nodes by their drawn rectangles (settings band included), so the reported `overlapping_node_pairs` match the arrangement; the solver's `port_scene_pos` anchors can differ from drawn anchors on data-node ports inside settings groups. Focused: `tests/test_transform_layout_ops.py`, `tests/automation/test_handlers_structure.py`.
- `layout.tidy` (MCP `layout_tidy`) is the canvas Tidy command. It calls `GraphSceneBridge.tidy_layout` (owner `ea_node_editor/ui_qml/graph_scene_mutation/tidy_layout_ops.py`; pure layout `ea_node_editor/graph/transform_tidy_layout.py`); with no `node_ids` it tidies the whole open scope. `mode` is `auto_layout` or `in_place`, `direction` is `auto`, `left_to_right` or `top_to_bottom`, and `column_gap` / `row_gap` set the spacing. The scene decides everything: selection normalisation, fixed-obstacle groups, collapsed Groups moved as one block with their hidden members and laid out at their collapsed size at every level, owner growth, the neighbour push, and the membership guard, whose conflict surfaces as `NO_EFFECT`. The handler only reports: it adds `straightened_edge_ids` / `skipped_edges` from the same wire classifier as `layout.straighten` (wires between arranged nodes) and `overlapping_node_pairs` (any drawn pair touching an arranged, moved or pushed node). `skipped_nodes` gains the reason `locked_group` for selectable nodes the scene held back: a Group holding a locked node, or a locked owner Group that would have to grow. `ops/structure.py` restates the mode/direction enums and default gaps so the client-side catalog never imports `graph/`; `tests/automation/test_catalog.py` keeps them in sync with `transform_tidy_layout.py`. Focused: `tests/test_graph_scene_tidy_layout.py`, `tests/automation/test_handlers_structure.py`.
- Group membership in handlers: an expanded Group owns the nodes inside its area, a collapsed Group keeps exactly the members it had when it was collapsed, and expanding makes room (the scene owns all of it). `group.wrap` (`ea_node_editor/ui/shell/automation/handlers/structure.py`, `wrap_group`) rejects ids that are not drawn (`_drawn_node_ids`: hidden inside a collapsed Group) with `INVALID_PARAMS` and `details.skipped_nodes` reason `hidden_in_collapsed_group`, before any mutation. `node.update` (`ea_node_editor/ui/shell/automation/handlers/nodes.py`) calls the dry-run `scene.expand_refusal_reason(node_id)` inside its validation block when `collapsed=false` would expand a collapsed node, and rejects the whole update with `NO_EFFECT` (the reason in `details.reasons`) when a locked Group would have to grow or no room exists; a successful expand moves neighbours aside and grows parent Groups in the same undo step. Moving a Group with `node.update` x/y carries what it holds through the scene's `move_node` (expanded: `GroupScope.contents`, the canvas drag set; collapsed: its listed members); the handler reports those ids as `carried_node_ids` from a position diff taken right after the move, and `move_contents=false` routes an expanded Group's x/y through `set_node_geometry` (frame only; `INVALID_PARAMS` on other nodes and collapsed Groups). The op descriptions in `ops/structure.py` and `ops/nodes.py` and the node-type text in `guidance.py` state these rules; the guidance tidy step keeps `membership_conflict_node_ids` (`tests/automation/test_mcp_server.py`). Focused: `tests/automation/test_handlers_nodes.py`, `tests/automation/test_handlers_structure.py`.
