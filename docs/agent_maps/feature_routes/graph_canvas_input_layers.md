## Routing Notes
- Port lookup, click-to-connect, wire-drop candidates, and Ctrl-drag rewire in `GraphCanvasInteractionState.qml` resolve nodes through `_sceneNodes()`, which reads the merged `visible_scene_nodes_payloads` (regular nodes first, then Groups). Do not point new port or hit-test code at `visible_nodes_payloads`, which excludes Groups.
- Group input overlays sit above the edge layer. Preserve explicit edge hit delegation there: use non-mutating `GraphCanvas.edgeAtScreen(...)` for hover/cursor checks and `GraphCanvas.handleEdgePressAtScreen(...)` for left/right press handling before Group drag or selection starts.
- The Group drag cursor belongs only on empty Group hit areas. Hovering an edge inside a Group should keep the edge cursor behavior, not the Group hand cursor.
- Bare Text annotation corner handles use the horizontal-resize cursor and ignore pointer Y deltas; their surface owns the content-measured height.
- Shift+node-body drag is PowerPoint-style: `GraphNodeHostGestureLayer` re-evaluates the dominant axis on every move event (so pressing/releasing Shift mid-drag applies) and zeroes the other delta before emitting. `dragFinished` carries that `axisLock`, and the release commit zeroes the locked axis after the grid and guide snaps (see the smart-guide release note below). Shift+corner resize forces the press-time aspect ratio through `GraphNodeResizeHandle._lockAspectRatioEnabled()`; Bare Text ignores it.
- Smart guides (alignment and equal-spacing snaps for node drag and resize) run one session per gesture in `GraphCanvasSmartGuides.qml` (`GraphCanvas.smartGuidesRef`, enabled by `prefs.smartGuidesEnabled`). `GraphNodeHostGestureLayer` emits `dragOffsetChanged(nodeId, dx, dy, axisLock, snapBypass)`, with Alt as `snapBypass`, re-read on every move like Shift. `GraphCanvasSceneState.setLiveDragOffset` stores only that intent and the raw offset; `_freezeLiveDragMembership` begins the move session, the snap resolves in `_applyLiveDragOffset` when the frame scheduler flushes (once per frame, never per pointer event), and `clearLiveDragOffset` ends the session. The first resolve that Alt does not bypass takes the gesture's snapshot through `GraphCanvasStateBridge.smart_guide_snapshot(node_ids, scene_rect, options)` (the exact viewport plus a margin; `options` carries the gesture's current `offset_x`/`offset_y`), and resolves read no Python property. The snapshot reads drawn rects from the viewport indexes (a stale index is refreshed without a viewport query) and leaves out the moving ids, every Group that holds a moving node, and the contents of moving Groups (`owner_backdrop_id` chains); hidden members of a collapsed Group have no rect. Zoomed out a viewport can hold over a thousand candidates, and indexing them in JS cost up to ~60 ms plus GC stalls, so the pure builder keeps at most `SMART_GUIDE_CANDIDATE_LIMIT` (128): the most relevant to the moving union moved by the offset (the moving rects stay at their stored positions), candidates sharing its row or column band first, nearest along the other axis, then the rest by straight-line rect-to-rect distance, ties and output in input order (`heapq.nsmallest`). The slot's map says whether it was `trimmed` (the explicit flag, so exactly 128 candidates never count as trimmed) and, when it was, `dropGapX`/`dropGapY`: the smallest gap along each axis from that union to a candidate it left out (rect to rect, 0 where they overlap). The controller retakes the snapshot after a zoom or view-centre change; after `invalidateSnapshot()`, which `GraphCanvasSceneLifecycle._clearTransientSceneState` calls on a scene mutation once any move session has ended, so a resize keeps its session on a fresh snapshot (the old snapshot's moving union survives, so a resize still ranks the new one at its moving corner); and, only for a trimmed snapshot, by the drop-gap rule. Equal spacing along X reads only the band of candidates that overlap the moving rect along Y, and along Y those that overlap it along X, so no left-out candidate can join either band before the union has moved `dropGapY` along Y or `dropGapX` along X; a snap moves the settled rect up to one threshold further. So the snapshot is retaken once |dx| + threshold >= `dropGapX` or |dy| + threshold >= `dropGapY` from the offset it was ranked around, but never before `resnapshotFloorPx` (40 screen px, straight-line) of travel from there, so a dense layout, whose drop gaps are small, retakes at most once per 40 px of pointer travel instead of every frame. Only the floor, and the retake interval below, let a left-out candidate join a band before the retake. On mixed row layouts with Groups at zoom 0.12 (20,000 frames of 2 px), no floor drew no spurious gap marker but retook nearly every frame; the 40 px floor retook 952 times with spurious-gap frames comparable to the old travel window's (19 against 30, a difference within noise; all 19 floor-bound). What the rule gains is alignment fidelity: 16% of those frames snap differently from an uncapped snapshot, against 34% under the old travel window, for 6x its 160 retakes. On the 1200-node stress fixture at zoom 0.12 the drop gaps are 2-117 scene units, well under the 333-unit floor, so retakes are floor-bound: 5 on a 2000-unit drag at 4 px a frame (1 under the old travel window), each 5 ms p50 / 9 ms p95 (`profileLastSnapshotMs`, slot plus JS index build; the Python slot alone 2.9 / 4.0 ms). Floor-bound, a fast drag would retake every frame or two, so a drop-gap retake also waits until `retakeMinIntervalMs` (80 ms, read through `_nowMs()`, which is `Date.now()`) has passed since the session's last snapshot; the session's first snapshot, a zoom or view-centre change and `invalidateSnapshot()` never wait, and each of them restarts the interval, as a retake does. The interval binds only above 500 px/s of pointer travel (40 px per 80 ms, 8 px a frame at 60 fps), so a slow drag keeps every retake and a fast one retakes at most about 12 times a second. On the stress fixture at 60 fps (a probe on a frame clock) a 2000-unit drag at 30 px a frame retakes once instead of 3 times at zoom 0.12 and 3 instead of 8 times at 0.25 (at about 6 ms a retake, roughly 0.8 instead of 2.3 and 1.1 instead of 2.8 ms a frame on average), while at 4 px a frame it retakes 5 and 12 times either way. The frames the interval holds back resolve on the older snapshot, so a fast drag gives back part of the fidelity: on the mixed layouts at 30 px a frame (5,120 frames) 28% of frames differ from uncapped with the interval, against 15% without it and 31% under the old travel window, and spurious-gap frames stay rare (7, 4 and 11); at 10 px a frame 16% differ with or without it, and at 2 and 4 px a frame nothing changes. A live frame whose retake the interval held back sets `_retakeHeld`, and a release (`resolveCommit`) after it keeps that snapshot, so the node lands where the frame showed it rather than on a guide only a later snapshot holds; after any other frame the release follows the frames' rule. A resize ranks around its moving corner's displacement, since a Group corner dragged across a zoomed-out view leaves the node's neighbourhood. `GraphCanvasSmartGuideEngine.js` indexes the candidates once per snapshot and never scans all of them per resolve: edge and centre alignment, plus equal spacing between neighbours that overlap on the cross axis with nothing between them. Equal spacing is skipped for an axis whose band holds more than `SPACING_BAND_LIMIT` (256) rects, while alignment still applies, and a sweep that exceeds its step budget bails out with no spacing for that call instead of hanging. The canvas cannot reach that band limit, since its snapshots hold at most 128 candidates; the engine keeps the guard for other callers. An axis snaps only when a guide line or gap marker shows it.
- Smart-guide release: `GraphCanvasNodeDelegate.onDragFinished` calls canvas `resolveDragCommitDelta(nodeId, rawDx, rawDy, moved, axisLock, snapBypass)` (`GraphCanvasRootApi.js` over pure `GraphCanvasLogic.dragCommitDelta`) before the live offset clears; its `resolveCommit` calls keep the snapshot the last live frame used when the retake interval held that frame's retake back (see above). A guided axis keeps the guide value, other axes grid-snap exactly as before, Alt skips guides and grid, and the Shift-locked axis is zeroed last. With grid snap on, no Shift lock, and exactly one axis guided, `gridSettledGuide` settles the guide against the grid value of the other axis: an alignment line on the guided axis (`GraphCanvasLogic.guideLineOnAxis`) holds at any value of the other axis, so that guide stays as resolved; a spacing-only guide is resolved again through `resolveCommit` from its own value with the other axis held at its grid value (axisLock `horizontal` holds Y and lets only X snap) and stays only if it snaps to that same value there (`GraphCanvasLogic.sameGuideSnap`), else both axes grid-snap. So the grid cannot move the node out of the row that justified an equal-spacing X, and the release never lands on a guide the drag did not show. An unmoved release (a plain click) never runs guides and meets the grid alone, and a modifier change without pointer motion applies at the next move or release. Resize: `GraphNodeHost.smartGuides` (set by `GraphCanvasNodeDelegate`) reaches `GraphNodeResizeHandle.qml`, which captures the controller at press (`guideSession`), waits for real pointer motion (Alt bypasses), snaps moving edges to the nearest candidate edge that keeps the minimum size after its own clamp and aspect lock (under an aspect lock the axis with the closer valid edge drives and the other follows), re-applies the content minimum height; when a guide crosses a text-wrap boundary that would break an active aspect lock (Shift or a surface-owned lock), rejects that snap and keeps the pre-guide proportional rect; drops lines the final rect no longer satisfies through `confirmResize`, and ends the session on release, cancel, or destruction; `GraphCanvasSceneLifecycle.resetCanvasSceneState` also ends resize sessions.
- Smart-guide overlay (`GraphCanvasSmartGuideOverlay.qml`; the [graph-canvas map](../subsystems/graph_canvas.md) owns its placement and cost): horizontal-gap markers sit in the node header band (`horizontalGapHeaderOffset`, 16 scene units below the top of the span the pair shares, never past its middle) and vertical-gap markers mid-span; gap labels are off by default (`showGapLabels`); the default colour is a faint orange picked by canvas-fill luminance, not the shell theme. Lines, gap lines and ticks are non-overlapping pieces on one hairline-cell grid (collinear pieces merge, crossings leave each shared cell to one piece while the piece pool has room), so the translucent colour does not paint a pixel twice. `GraphCanvasSmartGuides._publish` republishes gaps when only their shared span (`crossStart`/`crossEnd`) changes, and bumps `guideRevision` once per publish that changed anything; the overlay takes both arrays on that bump.
- A right press while `GraphNodeHostGestureLayer` holds a left press (`pressedButtons & Qt.LeftButton`), dragging or still under the drag threshold, marks the rest of that left press inert (`leftPressInert`): further motion starts no drag and the left release neither commits nor clicks, so nothing moves or selects under the open menu. Only a live drag is canceled, before the menu opens: `dragCanceled` clears the live offset and ends the guide session, which moves the host back, so the press is mapped again from its window position and the node menu opens under the pointer (a Group dragged over a wire opens the wire menu). The node-relative surface-claim and title-edit checks keep the event's own position. A plain right-click keeps its old behaviour. A Shift-locked drag can leave the pointer off the node; a right press there goes to whatever is under the pointer (the empty-canvas menu on empty canvas), and the drag ends through the gesture layer's `onCanceled` when that press takes the grab.
- `GraphNodeHostGestureLayer` owns the default node/body drag cursor. Suppress that open-hand cursor over surface-owned embedded interactive regions (`_surfaceClaimsBodyInteractionAt`) so live previews, table/folder panels, and inline controls do not look draggable while still allowing empty node body drag affordances.
- Empty-canvas left-drag marquee selection is directional: left-to-right selects only fully enclosed nodes, while right-to-left selects nodes crossed by the rectangle. Ctrl/Shift keep the same directional node hit rules and add to the current selection. Held `W` switches the same gesture to live logical-route wire selection; `W+Shift` adds to the existing edge selection and includes Hidden active-data routes.
- Plain Left/Right on the graph canvas is reserved for a selected ready PDF-mode Media Panel through `GraphCanvasActionRouter.navigateSelectedPdfPage(...)`; Ctrl+Left/Ctrl+Right jump to the source/target of exactly one selected wire. Keep Alt+Left scope navigation and text-field cursor movement guarded separately.
- A real wire drag reuses the existing `wireDragState`: activation requests one fingerprinted compatible-endpoint snapshot from Python, repeated moves and release reuse it, and malformed/role/generation-mismatched snapshots fail closed. Compatible ports reuse the existing rings rather than a new overlay; final graph mutation still revalidates the drop. Normal drop replaces, Shift appends, Ctrl moves the complete incident bundle, and Ctrl+Shift copies only the sole or explicitly selected incident edge; cancellation, original/incompatible release, and invalid bundles are no-ops.
- `GraphCanvas.nativeOverlaySuppressionActive` is the shared presentation fact for viewport interaction, live node drag, live resize geometry, and active wire drag. Explicit press/hold viewport gestures use `viewportInteractionHeld`; accepted wheel events begin timer-based suppression before mutating the view and detect viewer surfaces through `visible_nodes_payloads`. Native Model Viewer overlays switch temporarily to their lightweight proxy while suppression is true without clearing explicit activation; only a true left-background selection clear demotes them. Generic node press/resize handlers must not own viewer-session lifetime.
- Path Pointer node drops are whole-host targets above the background OS-path catcher but do not add mouse handlers. Accept one OS or Native Explorer path, update `path` and `mode` through one bulk command/history entry, and consume multi-item or locked/read-only drops with `Qt.IgnoreAction`; dropping the same inputs on empty canvas keeps the create-node route.
