## Viewer Surface Notes
- `COREX.Viewer.Session` is the generic public session data type. DPF viewer nodes return its exact `corex.viewer_session` handle rather than copying the session projection into node output; the worker session service remains authoritative. DPF nodes still select backend `dpf_embedded` explicitly; generic session services must not infer DPF when `backend_id` is empty. The neutral `viewer` package excludes DPF and its operator-catalog preflight, while `full` retains both.
- `nodes/ansys_dpf_data_types.py` owns both the DPF semantic catalog contribution and the sole definitions of every DPF runtime handle-kind string. `COREX.Ansys.DPF.Mesh` parents `COREX.Mesh.IMesh` and `COREX.Ansys.DPF.Model` parents `COREX.Fem.Model.IModel`; do not infer additional vendor relationships. Runtime `dpf_*` handle kinds remain transport markers and are not semantic type IDs.
- `execution/dpf_runtime/__init__.py` exposes only the lazy `create_dpf_runtime_service` factory. Concrete composition lives in `dpf_runtime/service.py`, DTOs and errors live in `dpf_runtime/contracts.py`, and internal callers import those owners directly rather than through package or compatibility reexports. Creating the service must not import PyDPF or PyVista; each optional backend remains loaded only on first use.
- In-memory DPF viewer materialization uses the concrete `COREX.Viewer.Dataset` semantic type with `dpf.viewer_dataset` as its handle-kind marker. Generic DPF object consumers discriminate `RuntimeHandleRef.data_type_id`, never duplicate or trust semantic identity in metadata. Concrete handle validators require both the semantic type ID and backend kind, and resolving consumers supply both expectations to the registry. Every generated output, including a single-candidate port and each List item, must prove its live value against the deduplicated primary-plus-accepted candidates before wrapping; unsupported or ambiguous values fail instead of being stamped with the primary type.
- DPF result/model caches own cache-scope handles and lease each hit once to the requesting run. Run cleanup removes only that run's ownership; stale entries release their cache scope, and reset releases model streams while warning and continuing after cleanup failures.
- `DpfRuntimeOperationsMixin.model_part_names()` in `execution/dpf_runtime/operations.py` owns the bounded model-part-name projection. It reuses the model resolver, reads only `metadata.mesh_info.part_names`, preserves provider order, duplicates, and nonempty whitespace, and returns a detached tuple of exact built-in strings. The projection accepts at most 4,096 names and 65,536 aggregate UTF-8 bytes; native supported-provider success remains deferred.
- Stored DPF CSV/PNG/VTU/VTM outputs use typed `COREX.DataTypes.Path` artifact refs with the active catalog schema, explicit lowercase format, deterministic integrity, and producer provenance. Multi-output materialization uses atomic prevalidation and best-effort rollback of attempted outputs without touching unrelated entries. Runtime metadata keeps only bounded artifact labels/counts; the artifact store resolves paths by ref/artifact ID.
- The DPF viewer node is a viewer-specialized DPF plot surface: QML exposes plot-like embedded interaction, cached preview, and fullscreen handoff behavior while the DPF session bridge and `DpfViewerWidgetBinder` keep the DPF/PyVista transport specialized underneath.
- Viewer summary metadata carries exact `time_values`/`value_ranges` while small and deterministic count/sample/hash summaries when large, from `_build_fields_container_metadata(model=...)` in `dpf_runtime/base.py`; consumers use counts and bounded samples without treating samples as complete series. The binder exposes exact display stats (component-aware, post-warp min/max with entity ids) through `ViewerHostService.viewer_render_stats(node_id)`.
- Camera state survives option-only and playback changes: `ViewerHostService` keys `_viewer_view_states` by a camera-relevant signature (session/backend/transport_revision/transport/data_refs) on both capture and restore, and migrates instead of clearing on preview-signature changes. The binder also snapshots/re-applies the live camera on same-session re-populates when the request carries no camera payload.
- Embedded DPF viewer demotion uses in-memory `ViewerPreviewCacheImageProvider` frames and transient camera state. Do not restore the old temp-PNG proxy preview or stored materialization path for hover/selection demotion.
- DPF result-file browse filters are declared on the relevant path `PropertySpec.file_filter` values in built-in and generated helper descriptors; keep extensions in shared filter constants so operator/helper path browse behavior remains metadata-driven.
- DPF inspector policy is add-on-owned in `property_edit_adapter.py`, registered through the common add-on adapter factory hook. It conditionally projects only the active scope/time selectors, preserves inactive values, uses chip lists for explicit set/time lists, moves remaining materialization controls under Advanced, and emits a compact resolved-configuration summary plus first-incomplete-group attention hints. The generic shell inspector supplies shared property plumbing only.
- `DpfMetadataOptionsService` resolves paths, stats files, and loads `dpf.Model` metadata off the UI thread. Its resolved-path/mtime signatures, bounded cache, same-path in-flight deduplication, revisions, stale-completion guard, retryable Loading/Ready/Empty/Error projections, and shutdown cleanup keep result, named-selection, cumulative-set, and time-value selectors responsive while retaining manual entry when DPF is unavailable.
- Curated workflow nodes live in `ansys_dpf_curated.py` (the original trio) and `ansys_dpf_curated_post.py` (the post-processing wave), all registered through `curated_catalog.py`. `DPF Result Source` loads a result file and model from one path; `DPF Result Fields` combines result type, time scoping, and mesh scoping into a fields-container output; `DPF Result Viewer` combines loading, scoped extraction, and embedded viewer session creation. `DPF Min/Max Envelope` reduces a scoped result over sets to per-entity envelope fields plus per-set/overall extremes with entity coordinates; `DPF Time History Probe` reshapes a scoped result into one curve per entity for the plot nodes; `DPF Stress Invariants` derives von Mises / principal S1-S3 (descending) / intensity / max shear; `DPF Mode Shape Viewer` is the modal variant of the result viewer with a `mode` selector and `frequency` output; `DPF Field Math` is the fixed two-input add/subtract/multiply/divide/scale node; `DPF Table Export` tabulates a result (entity id, nodal coordinates, set, time, components, magnitude) into a staged CSV.
- The curated post-processing nodes execute through `DpfRuntimeAnalysisMixin` (`ea_node_editor/execution/dpf_runtime/analysis.py`), which binds ansys.dpf.core operators in-process. Generated ellipsis/variadic pins such as `add_fc` and `min_max_*` declare List access in `operator_catalog.json`, so graph wiring uses universal Shift fan-in and ordered List matching rather than an unbindable special case.
- Generated and curated DPF descriptors contain only data ports, with Item/List/Tree access metadata regenerated in the committed catalog. Side-effect/whole-topology consumers use Tree access; scalar pins remain Item. Do not reintroduce execution/completed/failed descriptors or an ellipsis adapter layer.
- DPF readiness is centralized: result/model/field/mesh/export/viewer inputs declare unconditional requirements, `DPF Model` accepts result-file handle or path, Time Scoping accepts set IDs or time values, and mesh selection/model conversion requirements activate from existing selection/variant metadata. The generated operator loader requires explicit boolean input metadata and rejects pin-presence mismatches before factory execution. Keep defensive direct-plugin validation for invalid supplied values and direct test calls, but do not turn missing prerequisites into worker failures.
- Curated field-producing nodes expose `fields: COREX.Ansys.DPF.FieldsContainer` as their stable result contract. Applicable nodes persist `time_scope_mode` as `first_set`, `last_set`, `all_sets`, `set_ids`, or `time_values`; only the active selector is consumed. Legacy nodes with one populated selector infer that mode, while nodes with both populated selectors fail with actionable guidance instead of silently unioning scopes. Time History starts at `choose_scope`; Mode Shape deformation defaults to `auto` while ordinary Result Viewer remains `off`.
- Time scopings use the cumulative-set location (`dpf.locations.time_freq`, "TimeFreq_sets"), not the model's step-based "TimeFreq_steps" — set ids across the app are cumulative set numbers, and step-based scoping mis-reads them on multi-substep (e.g. modal) files.
- Library taxonomy is workflow-first: all generated `dpf.op.*` mirrors route to `Ansys DPF/Advanced/Raw API Mirror/<Family>` via `operator_family_path()` in `ansys_dpf_taxonomy.py` (the flat Operators bucket is retired), and the atomic duplicates (`dpf.result_file`, `dpf.model`, `dpf.mesh_extract`, plus operator-backed `dpf.result_field`/`dpf.field_ops`) sit under `Advanced` (`Building Blocks` / Raw API Mirror). Scoping/support helpers, the data-sources chain, viewer, and plot nodes keep their homes. `category_path` is not serialized into `.cxproj`, so demotions cannot break saved projects.
- The seven non-viewer curated nodes use `surface_family="dpf_workflow"` and `GraphDpfWorkflowSurface.qml`; Result Viewer and Mode Shape Viewer retain the existing viewer surface. The compact workflow surface exposes safe inline enums, exact next-action and Field Math B guidance, running/incomplete/error/ready/stale strips, and a bounded facts card. Searchable result/named-selection controls, explicit ID lists, and file browsing remain in the inspector.
- Run completion projects DPF outputs through `ui_summary.py` into `dpf_workflow_summary_lookup`. The execution-state bridge exposes only state, headline, detail, and short label/value facts; it never copies DPF handles, meshes, arrays, or full tables into QML and retains stale summaries after execution-affecting edits.
- The add-on contributes five read-only workflows under `Ansys DPF / Recipes`: View one result, Peak over all sets, Probe versus time, Stress invariant to CSV, and Compare first and last result. Provider resolution is local, then global, then bundled; bundled definitions exist only while the add-on is live, use fragment-helper graph payloads with deterministic drop-connect endpoints, and keep result-file paths empty.
- Curated Help resolves before raw-operator fallback for all nine workflow nodes. Library hover cards reuse the shared `ManagedToolTip` policy with bounded purpose/primary-port copy rather than expanding row height.
- The DPF viewer adapter accepts both `dpf.field` and `dpf.fields_container` runtime handles. Direct fields-container inputs are forwarded to viewer sessions without wrapping; single-field handles are still wrapped for transport compatibility.
- `examples/ansys_dpf/named_selection_time_result_viewer.cxproj` is the standalone, easy-open example for showing a chosen result type on a named selection at one time value in the embedded DPF Viewer.
- `examples/ansys_dpf/curated_result_viewer.cxproj` is the shorter example for the same workflow through the curated all-in-one viewer node.
- `scripts/mcf_dpf_section_resultants/gui.py` is the standalone MSUP MCF / Static Structural DPF section-resultant GUI. Keep large `.rst` handling metadata-first on file load; expensive coordinate-system scans and result/mesh reads should happen only through explicit scan/run paths scoped to the selected named selection and needed result sets. Its optional external selection input accepts Mechanical text exports as generated node IDs and CDB exports as selectable `NODE`/`ELEMENT` `CMBLOCK` components; node inputs transpose to fully-contained RST elements, element inputs scope directly, and imported IDs must exist in the RST mesh. Static mode supports one cumulative set, an inclusive range with stride, or all cumulative sets through a dedicated sequential path that reuses one model/stream/reference-mesh setup and retains compact per-set evidence instead of constructing a modal-shaped identity payload. Modal MCF parsing normalizes indentation-wrapped coordinate records in memory before reading rows, optional skip-first mode slicing must keep MCF columns aligned with shifted DPF modal set IDs, and modal `force_summation` should stay bounded by set batches for large MSUP runs. CSV/history/Excel output must keep global-origin moments separate from selected-reference local moments, projected section width/height/area should come from unpadded local-axis spans, Excel nodal-force exports should leave formulas in calculated cells, visualization refreshes should preserve the current camera after the first render, PyVista legends/rulers should avoid overlapping at the viewport bottom, and left input/settings/log content should collapse to a compact rail like the right visualization panel.
- Static Structural geometry in this tool is selected-set deformed geometry: read global nodal displacement at each chosen cumulative set, convert it to the RST mesh unit, form `X_deformed = X_reference + U`, and use that same coordinate state for construction-plane element/node membership, centroids, nodal moment arms, exports, and PyVista points. Optional follow-geometry motion fits a proper finite rigid transform directly from the initial tracking-node coordinates to each set, transports the initial origin/axes, recomputes the moving plane/scope, and supplies the moving origin as the explicit DPF `force_summation` summation point. Missing displacement/units, explicit attachments with fewer than three usable tracking nodes, non-finite data, or rank below two must fail instead of falling back to reference geometry; rigid-fit residual warnings, reference-versus-deformed scope changes, and authoritative DPF-versus-nodal parity stay visible in evidence. The narrow visualization-only exception is an implicit follow-geometry plane that supplies fewer than three tracking nodes: show the initial/reference mesh, plane, and coordinate system with a preview-only warning, suppress result overlays/animation, and retain selected-set displacement in the bounded cache so a corrected plane can restore the deformed view without reopening DPF. Extraction remains strict and never uses this preview fallback. Static Range/All visualization streams already-solved displacement fields on a background thread through one model/streams lifetime, stores shared topology once with bounded RAM-or-memmap displacement storage, and reuses frames captured during extraction. Its collapsible animation strip drives a 33 ms elapsed-time controller with Exact/Smooth, Once/Loop/Ping-pong, speed, and visual-only deformation scale controls. Playback updates persistent PyVista actors in place; interpolated mesh/frame/plane/scope and authoritative total arrows are visualization-only, while extraction evidence, exports, parity, and nodal arrows remain tied to exact solved sets. Configuration changes cancel and invalidate the session, stale generations are rejected, and unavailable deformation never falls back to reference geometry outside the explicit preview-only exception.
- Exact FSUM/NFORCE-style extraction requires `element_nodal_forces` records in the RST. Static extraction must preflight DPF result metadata before mesh/frame work, explain that reaction-force output is not an arbitrary-section substitute, and direct missing-data cases to Mechanical `Analysis Settings > Output Controls > Nodal Forces = Yes` plus a re-solve (solver equivalent `OUTRES,NLOAD,ALL`); changing PyDPF cannot recreate records omitted during the solve.
- Result History supports MSUP transient points and Static Structural Single/Range/All cumulative sets through the same Force, Moment, and Overlay plots. Static history validates the displayed set against its per-set visualization signature, prefers strictly increasing solved result values for the X axis with cumulative set IDs as the duplicate/non-monotonic fallback, retains both values in hover evidence, and snaps its in-place cursor to exact solved sets during smooth visualization animation.
- `examples/project_review_deck_airworthiness/rotor_llp_review_showcase.cxproj` uses the curated DPF Result Viewer node as a portable rotor-flange surrogate inside a Project Review Deck showcase; it should not require live Ansys, WebEngine rendering, or DPF execution in automated tests.
